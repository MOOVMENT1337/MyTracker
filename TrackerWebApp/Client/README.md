# MyTracker Client

React **JavaScript** + Vite в существующей папке `Client`. Сервер остаётся в `../Server`. React-компоненты управляют страницами, формами, модальными окнами, фильтрами и перетаскиванием; старые скрипты, HTML-вставки и демо-хранилище не используются.

## Запуск

Полный первый запуск с созданием БД и администратора описан в [корневом README](../../README.md#первый-запуск). Требуется Node.js 22.19+. Сначала запустите PostgreSQL и backend по [инструкции сервера](../Server/README.md). Затем откройте отдельный терминал PowerShell **в корне проекта**:

```powershell
cd .\TrackerWebApp\Client
npm ci
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Vite проксирует `/api` в `http://127.0.0.1:3000`. Оба терминала должны оставаться открытыми. Остановка — `Ctrl+C`; при следующем запуске достаточно `npm run dev` из `Client` и отдельно из `Server`. Команды ниже в этом README выполняются из `Client`.

Для стандартного адреса backend `.env` клиента не требуется. Если адрес отличается, создайте файл:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Укажите в нём нужный `API_PROXY_TARGET` и перезапустите Vite:

```dotenv
API_PROXY_TARGET=http://127.0.0.1:3000
VITE_API_URL=/api
```

`API_PROXY_TARGET` — адрес backend для локального прокси; `VITE_API_URL` — базовый путь API в браузере. При локальном запуске оставьте `/api`, чтобы запросы шли через Vite. Переменная `API_PROXY_TARGET` в окружении терминала имеет приоритет над файлом `.env`.

Войдите с логином и паролем, заданными серверной командой `admin:create`. Только если вы явно использовали локальный `npm run db:seed`, доступны `admin@tracker.com` / `admin123`. Оба способа инициализации оставляют новую базу без очередей и задач. Клиент не создаёт демоданные.

Администратор открывает «Панель администратора» → «Создать пользователя», вводит имя, email и пароль (8–128 символов), затем передаёт реквизиты сотруднику самостоятельно. Email — уникальный логин; вход по отображаемому имени также сохранён. Новая учётная запись не меняет сессию администратора. Должность `Administrator` сама по себе не предоставляет административных прав.

## Сборка и размещение

```powershell
npm run build
```

Результат — `Client/dist`. При существующем `dist` backend раздаёт его вместе с `/api`. После сборки клиента перейдите в сервер, соберите и запустите его с ранее настроенным `.env` и применёнными миграциями:

```powershell
cd ..\Server
npm run build
npm start
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000); отдельный процесс Vite в этом режиме не нужен. Остановите ранее запущенный backend перед `npm start`, чтобы освободить порт. При обновлении frontend повторите сборку. Для production задайте серверные `PUBLIC_URL` и `FRONTEND_URL` равными общему HTTPS-адресу приложения и завершайте TLS на reverse proxy. После этих команд текущая папка терминала — `Server`; для дальнейших команд клиента вернитесь в `Client`.

Внешний статический хостинг возможен при настройке SPA fallback, проксирования `/api` и HTTPS. `VITE_API_URL` позволяет задать отдельный адрес API при сборке, но размещение на другом сайте потребует иной cookie-политики: основной проверенный режим — общий origin / same-site. Docker-конфигурация сервера по-прежнему собирает только API; для неё размещайте `dist` на reverse proxy или запускайте клиент отдельно.

## Что сохранено

- Доска, все пять статусов, карточки и таймеры, «Мои задачи», очереди, поиск, фильтры, статистика, журнал.
- Модальное и отдельное представление задачи (`?taskId=...`), редактирование, удаление, комментарии, Ctrl/Cmd+Enter.
- Формы задач и очередей, автоматический предварительный ключ очереди, палитра, подтверждения удаления, уведомления.
- Имена и роли сотрудников, светлая/тёмная тема, английский/русский, боковая панель и исходные responsive breakpoints.
- Все **девять подключённых CSS-файлов скопированы побайтно**. Неиспользуемый старый `styles.css` не подключён. Font Awesome 6.5.1 и Inter включены локально из npm, без зависимости от CDN. Отдельных растровых изображений в исходной верстке нет; исходные иконки и эмодзи сохранены.

Изменения по требованиям: убраны регистрация и ссылки на неё, вместо подсказки с демопаролями указана выдача реквизитов администратором, добавлена необходимая форма создания сотрудника в существующей админ-панели. Ошибки, ожидание API и серверные ограничения обрабатываются в существующих формах. Cloudflare challenge из скачанного HTML не переносится: он не относится к интерфейсу приложения.

## API

| Сценарий | Запросы |
| --- | --- |
| Вход, восстановление и завершение сессии | `POST /auth/login`, `GET /auth/me`, `POST /auth/logout` |
| Пользователи | `GET /users`, `POST /users`, `PATCH /users/:id` |
| Очереди | `GET /queues`, `POST /queues`, `DELETE /queues/:id` |
| Задачи и статистика | `GET /issues`, `GET /issues/stats`, `GET /issues/:id`, `POST /issues`, `PATCH /issues/:id`, `DELETE /issues/:id` |
| Комментарии | Загрузка в задаче, `POST /issues/:id/comments`, `DELETE /issues/:id/comments/:commentId` |
| Справочники, история, настройки | `GET /metadata`, `GET /activity`, `GET/PATCH /settings` |

Все пути относительны к `/api`. Списки загружают все страницы по 100 записей; фильтрация и статистика выполняются сервером. Формы передают `version`, чтобы не перезаписывать чужие изменения. Черновик остаётся в форме при ошибке. Пользовательские данные и bearer-токены в localStorage/sessionStorage не записываются: используется серверная HttpOnly cookie и заголовок `X-Tracker-Browser` для защиты изменений.

Вход доступен только по логину и паролю. Кнопки внешних сайтов и серверный OAuth удалены. Экран входа и новые аккаунты используют тёмную тему и русский язык. Выбранные пользователем другие настройки продолжают сохраняться. При обычной инициализации создаётся только администратор, без очередей и задач. Для удаления уже существующих данных с сохранением администратора предусмотрена серверная команда `npm run db:reset`: см. [инструкцию очистки](../Server/README.md#очистка-существующего-трекера).

## Проверка

```powershell
npm run build
npm test
npm run test:empty
```

Playwright запускает собранный клиент и настоящий Express API с отдельным временным PostgreSQL-кластером/схемой через существующий серверный тестовый помощник. Рабочий `DATABASE_URL` не используется. Нужны PostgreSQL (`PG_BIN`, PATH или стандартный каталог 17 на Windows) и Edge. Для другой системы настройте `use.channel` в `playwright.config.js` или установите Chromium через Playwright. Перед тестами должны быть установлены зависимости **обоих** проектов. Занятый порт 4173 приводит к ошибке, чужой сервер не переиспользуется.

Проверки охватывают вход/выход и cookies, создание сотрудника и роли, запреты обычного пользователя, CRUD, комментарии, перетаскивание, фильтры, большие списки, настройки, конфликты, отсутствие задачи и истечение сессии. UI-сравнение рендерит исходник из `html+css+js` и React с одинаковыми данными и локальными шрифтами: 1440×1000, 375×812, 768×1024, 844×390, обе темы и языка; отдельно — модальное окно задачи, полная страница, создание очереди и настройки. Анимации отключены только при снимках, реальные взаимодействия проверяются с анимациями. Для сравнения тестовые пользователи явно получают прежние light/en; рабочие defaults остаются dark/ru. Отдельный `test:empty` проверяет обычную инициализацию: только администратор, отсутствие очередей/задач/журнала и внешнего входа, тёмная тема и русский язык, сохранение выбранных настроек, перезагрузка и выход. Его отчёт находится в `playwright-report/empty/index.html`.

HTML-отчёт со снимками и разностями: `playwright-report/index.html`; JSON: `test-results/report.json`. Сгенерированные отчёты не коммитятся. Исходные ограничения адаптивности, включая горизонтальную прокрутку доски и скрытые элементы верхней панели на телефоне, сохранены; редизайн не выполнялся.
